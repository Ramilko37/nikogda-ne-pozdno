# Спецификация визуальной доработки сайта Никогда не поздно

Дата: 1 ноября 2026 года. Получатель: frontend-разработчик.

Доработать существующий прототип после визуального аудита taste-skill: повысить читаемость, быстрее показывать условия помощи и сделать внутренние страницы компактнее. Сохранить визуальный образ фонда. Эта задача заканчивается проверенной локальной реализацией и отчётом до/после; публикация в неё не входит.

## Исходное состояние

Аудит выполнен на production-сборке: 11 страниц на ширинах 1440 и 390 px, главная дополнительно на 768 px. Горизонтального переполнения и сломанных изображений инспектор не обнаружил. На главной он определил преобладающий основной текст как 14 px и нашёл 16 текстовых блоков меньше 13 px. На телефоне заголовок страницы помощи занимает четыре строки, а блок бюджета на страницах программ предшествует информации о получателях помощи.

Скриншоты и JSON-отчёты находятся локально в `.taste-skill/audit/`. Эта папка не отслеживается Git; при передаче только репозитория снять исходное состояние заново. Общие сведения о проекте находятся в `README.md`, ограничения контента — в `docs/CONTENT_CHECKLIST.md`. Исторические результаты проверок не заменяют проверку новой реализации.

## Обязательные ограничения

- Сохранить Next.js App Router, TypeScript, текущий CSS/Tailwind и существующие компоненты. Новые зависимости, дизайн-система или универсальные конструкторы страниц не нужны.
- Использовать Source Serif 4 для заголовков и Golos Text для основного текста и интерфейса. Решение от 1 ноября 2026 года заменяет прежнее требование сохранять Cormorant Garamond и Manrope и согласует реализацию с §6 гайдлайна. Шрифты загружать локально, с поддержкой кириллицы и курсива Source Serif 4. Сохранить существующую палитру, логотип, Землю и четыре программы. Не менять камеру, текстуры, освещение и механику 3D ради этой задачи.
- Сохранить маршруты, `/about#team`, ссылки на документы, официальные названия программ, ФИО и полномочия команды, суммы и условия из `src/lib/content.ts`.
- Проект программы на 2027 год не превращать в действующую программу или отчёт о результатах. Географию и сроки сопровождать существующими оговорками.
- Платежи, отправка обращений и запись участников остаются недоступными. Не добавлять сбор персональных данных, внешнюю аналитику, контакты, отзывы, фотографии людей или показатели, которых нет в подтверждённом контенте.
- Сохранить `noindex, nofollow`, статичную замену Земли, автоматическую паузу при взаимодействии, reduced motion, клавиатурное взаимодействие и возврат фокуса.
- Выполнять наименьшее изменение в общих компонентах. Перед исправлением общего CSS проверить все его использования. Не дописывать очередной слой противоречащих переопределений в конец `globals.css`; менять применимое правило и удалять только связанные дубли.

Кнопку play/pause и аннотацию под Землёй не показывать (решение от 1 ноября 2026 года). Источники текстур остаются в `public/assets/earth/CREDITS.txt`.

## Общая типографика и доступность

| Роль | Требование |
| --- | --- |
| Основной текст | 16 px до 1100 px включительно, 18 px на desktop шире 1100 px; межстрочный интервал 1,5–1,7 |
| Вводный абзац | 18–20 px, без чрезмерно длинных строк |
| Важные статусы, условия доступности, предупреждение демоформы и результат её проверки | 16 px на всех ширинах |
| Второстепенные пояснения и подписи полей | Не меньше 14 px на всех проверяемых ширинах |
| Кнопки и ссылки навигации | Не меньше 14 px; подписи не обрезаются |
| Атрибуция изображений и второстепенная служебная информация | Не меньше 13 px; остаётся доступной |
| Заголовки | Согласованная адаптивная шкала; ориентир внутренних h1 — 36–44 px на телефоне и 56–72 px на desktop; главный hero сохраняет собственный масштаб |

Настроить существующие общие стили по ролям. Не выравнивать все тексты по одному размеру. Цифры-маркеры огоньков могут быть меньше основного текста, если у кнопки остаётся доступное полное название и рядом существует читаемый список программ.

Содержательные абзацы использовать в основном тёмном цвете палитры. Приглушённый цвет оставить для второстепенных сведений. Контраст обычного текста — не ниже 4,5:1, крупного — не ниже 3:1. Предупреждение инспектора о желательных 7:1 не считать автоматически нарушением доступности.

Длина строки основного текста — ориентировочно 45–75 знаков на широком экране. На телефоне сохранить поля 16–20 px. Элементы управления должны иметь удобную область нажатия не меньше 44×44 px; не растягивать обычные ссылки внутри абзаца до размеров кнопок. Фокус виден и не обрезан. При увеличении текста до 200% информация и действия остаются доступны.

## Изменения по страницам

### Главная

Сохранить композицию первого экрана на desktop: текст слева, большая Земля справа. Не заменять её новым направлением taste-skill.

На телефоне сохранить порядок: заголовок, описание, действия, статус проекта, Земля, список программ. Уменьшить лишние промежутки внутри блока Земли; список должен следовать за сценой и её компактной подписью без высокого пустого промежутка. Нейтральное приглашение выбрать программу сделать компактным. При выборе программы карточка показывает полный текст, не перекрывает кнопки и не обрезается.

Укрупнить статус проекта, список программ и подписи управления. Атрибуцию и пояснение, что огоньки не являются адресами помощи, сохранить. Области нажатия огоньков не уменьшать.

Заменить заголовки информационных разделов на конкретные:

| Раздел | Новый h2 |
| --- | --- |
| О фонде | У каждого должна быть точка опоры |
| Программы | Четыре направления помощи |
| Порядок | Как устроена помощь |
| Открытость | Документы и отчётность |

Если над новым заголовком стоит подпись с тем же смыслом, убрать дублирующую подпись. Тексты миссии и фактические пояснения сохранить. Финальный блок поддержки и название фонда сохраняют эмоциональный тон.

### Каталог программ

Использовать h1 «Программы фонда». Сохранить вводное описание, статус проекта, четыре строки программ и оговорку о географии. На телефоне названия и описания читать в одной логической колонке; иконка не должна существенно сужать текст. Вся строка остаётся ссылкой, доступной с клавиатуры.

### Все четыре страницы программ

Официальный h1 и содержание программы сохранить. Не сокращать название «Никогда не поздно стать самостоятельным» ради количества строк. Допускаются три строки на узком экране, если слова не обрезаются и заголовок не вытесняет всё описание.

Установить следующий порядок в DOM и на телефоне:

1. Ссылка «Все программы», категория, название, краткое описание и статус проекта.
2. «Кому предназначена» и «Для чего нужна помощь».
3. «Что предусмотрено» с полным существующим перечнем.
4. «Как принять участие» со статусом доступности, условиями и ссылкой на `/get-help`.
5. Компактный блок «План на 2027 год»: бюджет, пояснение «Это план расходов, не собранная сумма», география с оговоркой, период и ссылка поддержки.
6. Другие программы.

На desktop использовать читаемую колонку содержания и компактную сводку ниже; убрать нынешнюю короткую боковую колонку, оставляющую пустоту вдоль длинного текста. В сводке разрешена сетка для бюджета, географии и периода, складывающаяся в одну колонку на телефоне. Не дублировать сведения для разных разрешений и не менять порядок фокуса через CSS.

### Поддержать фонд

H1: «Поддержать фонд». Существующее описание способов участия сохранить.

После вступления разместить два обычных якоря: «Деньгами» на `#donation` и «Другие способы участия» на `#other-support`. Оба доступны с клавиатуры, целевой раздел не скрыт шапкой. Без новых вкладок, модальных окон и клиентского состояния для навигации.

Порядок контента: вступление и якоря, форма, другие способы участия. На desktop допустимы две колонки с формой слева и другими способами справа; DOM и чтение с клавиатуры следуют этому порядку. На телефоне форма не уходит за четыре текстовых блока.

Внутри формы сразу после h2 и до полей показать текст: «Демонстрационный режим. Платежи пока недоступны. Деньги не списываются, данные карты не запрашиваются». Перенести существующее предупреждение, не дублировать его внизу. Сохранить подпись кнопки «Проверить выбранную сумму · демо», ограничения суммы, переключатели и сообщение «Пожертвование не оформлено» после подтверждения.

Перед перечнем других способов участия показать существующее сообщение о недоступности передачи вещей, записи волонтёров и партнёрства. Сохранить все четыре способа и их описания. Не добавлять неработающие кнопки записи.

### Получить помощь

H1: «Получить помощь». Сразу под вводным описанием расположить заметный блок «Приём обращений пока недоступен» с существующим пояснением. Сохранить статус проекта программы рядом с этой информацией.

Далее последовательно разместить аудитории и ссылки на программы, условия, географию и порядок обращения. Убрать пустую левую колонку на desktop. Шаги обращения оформить семантическим упорядоченным списком; сохранить сведения об индивидуальном решении и отсутствии установленного срока рассмотрения.

### Документы и отчёты

H1: «Документы и отчёты». Сократить расстояние от вступления до документа. При 390×844 px название и ссылка на DOCX должны целиком помещаться в первом экране при стандартном масштабе.

Сохранить название файла в интерфейсе, дату, формат DOCX, статус проекта, оговорку о плановых показателях, отсутствие годовых отчётов и полный перечень механизмов контроля. Иконка скачивания не должна сдавливать название. На desktop согласовать левый край вступления и основного блока, ограничив длину текстовых строк.

### О фонде

H1: «О фонде». Сохранить фактическое вступление и миссию. Уменьшить промежутки между заголовком миссии и её содержанием на телефоне.

Сохранить `#team`, всех шесть участников, группировку по органам управления и все описания полномочий. Имя и должность держать вместе; расстояние между участниками должно быть меньше расстояния между органами управления. Не добавлять пустые места под будущие фотографии.

Документы и контакты оформить компактными разделами с существующими пояснениями и ссылками, без отдельного высокого экрана на каждый короткий текст.

### Контакты

H1: «Контакты фонда». Сразу после краткого вступления показать «Контакты пока не опубликованы» и существующее пояснение. Уменьшить разрыв между заголовком и текстом. Сохранить оговорку, что Москва и Московская область являются планируемой географией, а не адресом офиса, и ссылку на программы.

## Применение taste-skill

Запустить инспектор до и после изменений. Исправить подтверждённые проблемы читаемости, переполнения, перекрытий и композиции. Не стремиться к нулю формальных замечаний ценой утверждённого дизайна.

Допустимы при объяснении в отчёте: курсив фирменных заголовков, трёхстрочный заголовок главной, длинные официальные названия, атмосфера и свечение Земли, маска для читаемости текста, функциональные разделители списков и форм, нумерация реальных последовательных шагов. Не добавлять четыре фотографии, видео или анимации только ради прохождения проверки. Настоящие фотографии команды — отдельная будущая задача.

Не скрывать текст от инспектора и не использовать исключения для мелкого текста, плохого контраста, сломанных изображений или переполнения.

## Порядок реализации и приёмка

Сначала общая типографика, затем порядок блоков, затем отступы и визуальная сверка. Не делать отдельный рефакторинг проекта. Использовать имеющиеся тесты; новые проверки добавить в текущий набор только для изменившегося поведения.

Проверить все 11 маршрутов: `/`, `/about`, `/programs`, четыре `/programs/[slug]`, `/help`, `/get-help`, `/reports`, `/contacts`.

| Проверка | Критерий приёмки |
| --- | --- |
| Скриншоты | Все страницы на 390×844, 768×1024 и 1440×900; одинаковые размеры и состояния до/после; полный просмотр, не только первый экран |
| Узкий экран | Проверить 320×800 на всех маршрутах: нет горизонтального скролла, обрезанных слов, перекрытий и недоступных действий |
| Текст | Выполнены минимальные размеры по ролям, контраст проверен по фактическим цветам; увеличение текста до 200% не скрывает информацию |
| Программы | На телефоне «Кому предназначена» предшествует бюджету; официальные названия, суммы и оговорки сохранены |
| Помощь | Предупреждение о деморежиме расположено перед полями; оба якоря ведут в нужные разделы; подтверждение суммы не оформляет платёж |
| Навигация | Мобильное меню, обычные ссылки, `/about#team`, переходы программ и скачивание исходного DOCX работают |
| Земля | Все четыре программы выбираются, список синхронизируется, Escape закрывает карточку и возвращает фокус; автоматическая пауза при взаимодействии, reduced motion и `/?static` сохраняют работоспособность |
| Формы и фокус | Поля имеют подписи, фокус виден, обход клавиатурой соответствует чтению, нет положительных `tabindex` |
| Регрессии | Production-сборка, TypeScript и существующий Playwright-набор проходят; селекторы обновляются только под намеренные изменения, проверки не ослабляются |

Добавить компактную регрессионную проверку нового мобильного порядка «аудитория до бюджета» для четырёх программ и проверку доступности якорей на `/help`. Дополнить существующий тест демоформы проверкой расположения предупреждения перед полями. Размеры и отступы, подтверждённые визуально, не покрывать отдельным тестом на каждое CSS-значение.

Команды из корня проекта с учётом локального RTK:

```sh
rtk proxy npm run build
rtk proxy npm run typecheck
rtk proxy npm test
rtk git diff --check
```

Для taste-skill использовать установленный каталог навыка; на текущей машине это `/Users/rr/.codex/skills/taste-skill`. Инспектировать production-сервер, передавая отдельные каталоги `--out` для каждого маршрута и состояния. Не перезаписывать исходный аудит результатами после изменений. Зафиксировать фактические результаты и ограничения окружения; не переносить исторические заявления об успешных тестах.

Результат передачи: небольшой дифф, сопоставимые скриншоты, результаты команд, оставшиеся замечания taste-skill с объяснением исключений и краткое описание изменений. Не добавлять изображения аудита в публичные ресурсы сайта. Реализация считается принятой по требованиям этой спецификации, а не по числу баллов taste-skill.
